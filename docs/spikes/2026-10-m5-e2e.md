## Setup notes

  anything changed.
- Jellyfin was stopped and `plugins/Currents_0.4.0.0` was moved to `dev/data/plugins-disabled/`. The first deploy
  installed the new build as `Currents_0.4.0.0`, because `Directory.Build.props` still said 0.4.0 (Defect 1). After the
  fix, `dev/deploy-plugin.sh` deployed `plugins/Currents_0.5.0.0`.
- Sessions without passwords: the browser and two API sessions (alice and the admin user `dev`) logged in with Quick
  Connect, authorized from the admin API key (`POST /QuickConnect/Authorize?code=...&userId=...`). Quick Connect was
  already enabled on the dev server. No password was set or reset.
- Search-add and per-user segment checks need a user session: requests with the admin API key carry no user, so
  `SearchItemFilter` answers 404 and `SegmentRequestFilter` has no top version to judge (Finding 2).
- The admin page was driven with targeted DOM reads (no full page snapshots), so no configuration value reached a
  transcript.
- At the end: configuration and `state.json` restored from the saved copies (byte-equal; `users.json` was never
  changed), Verify library re-created the six titles Purge had removed (Gladiator, Interstellar, Breaking Bad and three
  catalog titles), the test collection was deleted, the stack runs on the normal compose configuration
  (`CURRENTS_COMPAT_TEST_VERSION` empty) with Currents 0.5.0.0 Active. API sessions and the browser device were logged
  out, browser storage cleared, Playwright files and helper files deleted.

## Defects found
1. **Assembly version still 0.4.0.0** (fixed, 09d4a82). `build.yaml` said 0.5.0.0 but `Directory.Build.props` kept
   `0.4.0`/`0.4.0.0`, so Jellyfin listed the new build as Currents 0.4.0.0 and `dev/deploy-plugin.sh` deployed it to
   `Currents_0.4.0.0`. Bumped `Version`, `AssemblyVersion` and `FileVersion` to 0.5.0; redeployed: `Currents 0.5.0.0 Active`.
2. **Diagnostics cache line showed `NaN% from cache`** (fixed test-first, b7fcb69). Jellyfin's JSON options drop null
   properties, so a cache with no lookups arrives without `HitRate`, and `c.HitRate === null` let `undefined` through.
   Now `== null`; pinned by `PagesTests.Admin_page_cache_line_treats_a_missing_hit_rate_as_no_lookups`. Re-checked in the
   browser: `no lookups yet`, then `67% from cache`.
3. **First collection listed in premiere-date order** (open, intermittent). Repro seen once: the first sync with
   Collection ticked, which also created Jellyfin's Collections library and ran a library scan. `JellyfinCollectionSync`
   sets `DisplayOrder = "Default"` and calls `UpdateItemAsync` after `CreateCollectionAsync`; collection.xml holds
   `Default`, but the database item said `PremiereDate`, and `GET /Items?ParentId={boxset}` listed by premiere date. A
   metadata refresh did not change it (the BoxSet is locked); setting it again through `POST /Items/{id}` stuck. Four
   re-creations (with the Collections library present, after removing it, after a restart) kept `Default`. Suspected: a
   race with the refresh Jellyfin queues inside `CreateCollectionAsync` (`FullRefresh`, `ForceSave`) or the library scan
   started by the new Collections library, which saves its own copy of the item after ours. Fix options, which need a
   decision: (a) re-assert `DisplayOrder = "Default"` on every sync (simple, but overrides an admin who picks another
   order); (b) wait for `IProviderManager.RefreshCompleted` for the new BoxSet before setting it (keeps the admin's later
   choice, more moving parts).
4. **Purge leaves the titles listed in Jellyfin** (open). Purge deletes every Currents folder, so `Movies/` and
   `Shows/` end up empty; Jellyfin treats an empty library folder as possibly offline and skips it (`Library folder ...
   is inaccessible or empty, skipping`), so the refresh removes nothing. The titles go away only when a later sync
   writes files into the folders; if every catalog is unticked they stay as dead entries. Fix options, which need a
   decision: (a) after deleting the files, remove the Jellyfin items under the Currents folders through
   `ILibraryManager` (Integration); (b) keep a plugin-owned placeholder file in each library root so the folder is never
   empty; (c) document it and tell users to run a sync or a library scan.

## Findings (not defects; need a decision or a note)
1. A successful AIOStreams search writes no log line, so "the next open searches AIOStreams again" is shown by the
   diagnostics counters and the open time, not by a log line as the brief expected.
2. `GET /MediaSegments/{itemId}` judges the caller's top version. With the admin API key there is no user, so the list is
   empty; the same holds for a user who has not opened the title yet. Clients always open the title first, so the skip
   prompt is unaffected; the brief's "admin key lists an Intro" holds only with a user session.
3. Search-add needs a user session; with an API key `SearchItemFilter` answers 404 (by design: `mayAdd` needs a user).
4. Jellyfin collapses collection members into the BoxSet for item queries without a user, so `GET /Items?IncludeItemTypes=Movie`
   with the API key listed 4 Currents movies plus the BoxSet; with the `dev` session it listed all 24.
5. jellyfin-web shows the Skip Intro button for a few seconds when playback enters the segment and again whenever the
   on-screen controls are shown inside it.
6. The far-from-reference case comes up naturally on episodes: *Breaking Bad*'s pilot (58 min) gets no markers because
   TheIntroDB episodes use the series runtime (48 min) as the reference (the documented limitation).
7. Saving the admin page rewrites each catalog's stored `Name` to the display name from the manifest (for example
   `tmdb.trending` -> `TMDB Trending`, `Movies` -> `Movies Search`). Harmless; the restore put the old names back.
8. Streaming a title whose only source is the "No streams found" placeholder (*Other Mommy*) answers 500
   (`StreamingHelpers.GetStreamingState`); clients see the placeholder name first. Not new in M5.
9. Purge leaves the Currents collections in place; the re-synced titles keep their item ids and rejoin them.
10. The dev server has no fixed name, so Jellyfin shows the container hostname; each `--force-recreate` changed it
    (`093e3cd2768c` -> `94c35c951031`). Cosmetic.
11. Jellyfin 12.1 names its own segment task "Media Segment Scan" (every 12 h), not "Extract media segments"; README,
    architecture, spec and admin page now say so (0536708).
