## Decisions
- M2 proceeds with ephemeral synthetic versions (no persisted version rows), and MUST add:
  1. An MVC filter in `Integration/` that resolves `GET /Items/{syntheticVersionId}` (and any other item lookup by a synthetic id the client makes, e.g. `/Users/{uid}/Items/{id}`) to the base item.
  2. `MediaStreams` on every version, from AIOStreams parsed data or RemuxDB, with a one-time cached probe as fallback.
  3. `RunTimeTicks` set on the base item (from metadata runtime or the first probe).

  Headline: **synthetic version ids must resolve as items.** The web client assumes every MediaSource id is a library item id.
- Because S4 shows the web client direct-plays `.strm` URLs, M1 degraded mode requires a client-reachable `StrmBaseUrl`, and in degraded mode clients may follow the redirect to the final stream URL themselves. M2's decorator removes this by forcing streaming through Jellyfin (`SupportsDirectPlay=false`).
- M1 end-to-end refinement of S4 (2026-10-01, real AIOStreams streams): the web client only direct-plays the `.strm` URL when the probed source is browser-compatible (seen with an h264/aac 720p source). 4K HEVC Dolby Vision, TrueHD or EAC3 sources go straight to server HLS and the browser never opens the `.strm` URL. Because the server's ffmpeg also opens the `.strm` URL, `StrmBaseUrl` must be reachable by both clients and the server: `http://localhost:8097` fixed browser direct play in the dev stack but made every server transcode fail (`Connection refused` inside the container), while the host's LAN address worked for both. M2's decorator (always stream through Jellyfin) removes this trade-off.
- Re-test S1 and S4 on Android TV, Swiftfin, Findroid and Infuse during M2 (client matrix).
- Also noted for M2: `GetPlaybackMediaSources` runs several times per playback start and on every seek or transcode restart, so the resolved-stream cache is required, and resolve must never call AIOStreams per segment.
