Docker on host port 8097, against the maintainer's real AIOStreams and AIOMetadata instances (TorBox/Torrentio,

## Setup notes
- Before deploying, Jellyfin was stopped and the old M1 plugin folder `plugins/Currents_0.1.0.0` was **moved** (not
  deleted) to `dev/data/plugins-disabled/`. The other folder, `plugins/Jellyfin.Plugin.Currents`, was **not** moved:
  it is not a second install but the plugin's data folder (`BasePlugin.DataFolderPath`, holding `state.json` and now
  `users.json`), so it must stay.
- `dev/deploy-plugin.sh` deployed to `plugins/Currents_0.2.0.0`. It ran twice (once more after the admin-page fix
  below).
- Users `alice` and `bob` were created with `POST /Users/New`. Admin config (via the plugin configuration API, original
  saved first): default AIOStreams URL cleared, `EnableVersions = true`. Alice saved her own AIOStreams manifest URL
  with `PUT /Currents/user/settings` (JSON body, her own token). Bob has no config.
- A temporary admin user was created for the admin-page checks and deleted afterwards. The original plugin
  configuration (default AIOStreams URL, `EnableVersions = true`, all other settings) was restored at the end and
  compared equal to the saved copy.

## Defects found and fixed
1. **Admin users table showed "own (user.OwnConfigHost)"** instead of the host, and the override placeholder would have
   read "saved on user.OverrideHost". jellyfin-web runs plugin configuration pages through `translateHtml`, which
   replaces every dollar-brace `{...}` placeholder with a translation (logging "Translation key is missing from
   dictionary: user.OwnConfigHost"), so JavaScript template literals in `configPage.html` break. Fix: string
   concatenation instead of template literals, and a test (`PagesTests.Admin_page_has_no_template_placeholders_that_jellyfin_web_would_translate`)
   that fails on any dollar-brace in the admin page. Commit `fix: admin page avoids template literals that jellyfin-web
   rewrites as translation keys`. Verified in the browser after redeploying. (`/Currents/user` is served directly, not
   through jellyfin-web, so its template literals are fine.)

## Findings (not fixed; need a decision)
1. **Jellyfin logs version tokens.** Jellyfin's `TranscodeManager` logs the full ffmpeg command line at Information
   level, so every playback writes `http://127.0.0.1:8096/Currents/play/s/{token}` with the real token into the
   Jellyfin log (`SecretMasker` covers only Currents' own log lines). The same already happens with `.strm` signatures
   in degraded mode (M1). Impact is limited: the token only works from loopback or the server's own addresses and
   expires after `VersionTokenHours` (24 h), and the log is admin-only. Combined with the same-host reverse-proxy
   limitation in `docs/architecture.md`, someone who can read the log could replay a token from outside for up to 24 h.
   Options: accept and document (current state), shorten `VersionTokenHours`, or add a Serilog filter/enricher that
   masks `/Currents/play/s/` in Jellyfin's own log events (touches Jellyfin's logging pipeline).
2. Non-fatal hls.js console errors during playback (`otherError internalException`, and a burst of `bufferFullError`
   during the 4K episode). Playback continued; these come from the browser's buffer with large stream-copied 4K
   segments, not from Currents.
3. Pressing **Save** on the self-service page without changes stores the displayed (effective) preferences and
   auto-select as the user's own (they equal the server default here). Harmless, but the user then no longer follows
   later changes to the server default or an admin override for those fields until they press "Reset preferences to
   the server default". Candidate UI tweak for later. (Alice's record was reset after the check.)
