# M4 end-to-end check (dev stack)

Date: 2026-10-03 (UTC). Plugin: Currents 0.4.0.0 (branch `feat/m4`, redeployed at head b89574d). Server: the `dev/`
stack, Jellyfin 12.1.0 in Docker on host port 8097, against the maintainer's real AIOStreams and AIOMetadata
instances and the public RemuxDB. Browser: Playwright (Chromium) on jellyfin-web 12.1. No secrets, tokens, upstream
host names or manifest UUIDs are recorded here.

## Setup notes
- The plugin configuration, `state.json` and `users.json` were saved to a git-ignored scratch folder (mode 600) before
  anything changed.
- Jellyfin was stopped and `plugins/Currents_0.3.1.0` was **moved** to `dev/data/plugins-disabled/`.
  `dev/deploy-plugin.sh` deployed `plugins/Currents_0.4.0.0`; it was deployed a second time after the fix commits up
  to b89574d (RemuxDB 5 s budget, track-choice mapping against the pre-probe display, Accept-Encoding reserved, proxy
  failure logging, `EnableSubtitles` enforced).
- Users `alice` (own AIOStreams config) and `bob`: the admin set new dev-only passwords with `POST /Users/{id}/Password`
  (approved by the user after a first permission refusal, see "Refused actions"). Alice's web session used the login
  form; the API checks used her session token.
- Subtitle search/download calls need subtitle-management rights, which alice does not have (403), so check 6 used the
  admin API key. With an API key there is no user in the request, so the provider queried the default AIOStreams config.
- Configuration difference after the upgrade: the live configuration has exactly three keys the 0.3.1 copy lacked
  (`EnableRemuxDb`, `EnableSubtitles`, `RemuxDbUrl`, all defaults: both switches on). The deploy brought no other change.
  Check 9 turned `EnableRemuxDb` off and back on; at the end the live configuration equals the saved copy on every saved
  key plus those three defaults. `users.json` equals the pre-run copy.
- At the end: API sessions logged out, the browser device deleted and its storage cleared, token, password, API-key and
  helper files removed.

## Defects found
1. **Embedded text subtitle on a transcoded Currents version cannot play (burn-in fails).** Repro: Gladiator, the
   `Comet` 66.6 GB version (`99f9dd93...`), choose `English - SUBRIP`, Play in jellyfin-web 12.1. Evidence:
   PlaybackInfo for that version and subtitle index returns `DeliveryMethod: Encode`, `IsExternal: false` (also with a
   profile that offers External srt/vtt); the transcode URL has `SubtitleMethod=Encode`; ffmpeg log: `Unable to open
   /config/data/subtitles/99/99f9dd93-.../10.srt`, `Error opening output file`, exit 254; `GET .../hls1/main/-1.mp4` 500;
   no subtitle extraction line in the log. Jellyfin normally extracts the stream to that file; here nothing created it.
   Suspected: `Integration/CurrentsMediaSourceManager.cs` (media source for HTTP/`currents://` paths and subtitle
   delivery/extraction; `SupportsExternalStream` is set in `VersionSourceBuilder.cs` but the response shows `null`).
   Whether this is also true of any HTTP-source item in Jellyfin 12.1 was not checked.
2. **Anonymous request to the subtitle stream route answers 500.** `GET /Videos/{id}/{versionId}/Subtitles/2000/0/Stream.vtt`
   without a key: `InvalidOperationException: Sequence contains no matching element` in `SubtitleEncoder.GetSubtitles`
   (the version's streams, resolved without a user, lack index 2000). With the `ApiKey` from the DeliveryUrl it is 200.
   Low impact (clients always send the key); expected 401/404. Suspected: `Integration/CurrentsMediaSourceManager.cs`
   (downloaded-subtitle streams added only for user-scoped lookups).

## Findings (not defects; need a decision or a note)
1. The DeliveryUrl of an external subtitle carries the user's session token as `ApiKey` (standard Jellyfin behavior).
2. Trailers: Jellyfin's TMDb provider also fills `RemoteTrailers`, so on a dev server with TMDb enabled the Currents
   trailer provider cannot be told apart from it (the Currents list is capped at 5).
3. The web player made no request for the downloaded subtitle (`Stream.vtt`) and rendered no text for it in headless
   Chromium, even though the route returns 200. Not confirmed as a plugin problem; needs a check in a real browser.
4. Downloaded subtitles keep the upstream format (`.eng.vtt`), not `.srt` as the brief expected.
5. The web "Edit subtitles" dialog and the admin Media section were not driven in the browser (rights; no admin web login).
